# industrial-iot-platform
**工业物联网边缘采集与数据应用平台**

一个面向工业现场的开源工业物联网平台，覆盖工业设备数据采集、边缘网关管理、数据接入与处理、工业应用及组态可视化等环节。

项目采用分层架构与模块化设计，旨在构建一套从工业现场设备接入到上层业务应用的完整工业物联网解决方案。

## 一、项目介绍

本项目主要围绕工业物联网的五个核心层次展开：

1. **工业应用层**：面向工业业务场景，提供设备监控、报警管理、生产监控、能耗分析等应用。
2. **组态可视化层**：提供组态画面编辑、设备点位绑定、实时数据展示及运行时渲染能力。
3. **工业数据中台**：负责工业数据接入、标准化处理、时序存储、数据查询及分析。
4. **网关配置管理平台**：负责工业网关、设备、通信驱动及采集点位的统一管理，实现网关配置下发与运行状态监控。
5. **工业边缘网关**：负责连接工业现场设备，通过不同工业通信协议采集设备数据，并完成数据转换、缓存及上报。

通过上述模块协同工作，实现工业现场设备与上层工业应用之间的数据互通。

### 2.2 数据流转

工业设备产生数据后，整体数据流转过程如下：

```
工业现场设备
     │
     ▼
工业边缘网关
     │
     │ 协议采集、数据转换
     ▼
MQTT 消息通道
     │
     ▼
工业数据中台
     │
     │ 数据解析、标准化、存储
     ▼
数据服务
     │
     ├──────────────┐
     ▼              ▼
工业应用         组态可视化
```

### 2.3 网关配置下发

网关配置管理平台负责控制工业网关的采集行为：

```
网关配置管理平台
       │
       │ 创建采集配置
       ▼
MQTT 配置消息
       │
       ▼
工业边缘网关
       │
       │ 解析并应用配置
       ▼
设备连接与数据采集
       │
       │ 返回配置执行结果
       ▼
网关配置管理平台
```

平台可以对网关的设备、通信参数、采集点位及采集周期进行配置，并将配置下发至对应网关。

## 四、各项目功能说明

### 4.1 工业边缘采集层（edge）

负责工业现场设备接入、数据采集及边缘侧处理，是整个工业物联网系统的数据来源。

#### industrial-gateway：工业设备数据采集网关

基于 C++ 开发的工业边缘采集程序，主要负责连接 PLC、CNC、DCS 等工业设备，通过不同工业通信协议获取设备运行数据。

主要功能：

- 工业通信协议驱动。
- 工业设备连接与管理。
- 设备数据采集。
- 数据格式转换与标准化。
- 本地数据缓存。
- MQTT 数据上报。
- 网关配置加载与动态应用。
- 网关运行状态及日志管理。

初期重点实现典型工业通信协议的接入，采用统一的驱动接口，便于后续扩展更多设备及协议。

#### video-gateway：视频采集网关

负责工业现场摄像头及视频设备的接入，独立处理视频流相关业务。

主要功能：

- 视频设备接入。
- 摄像头发现与管理。
- RTSP 视频流接入。
- ONVIF 设备管理。
- 视频流解码与处理。
- 视频截图。
- 视频流转发。
- 视频设备状态监控。

视频网关与普通工业数据采集网关分开设计，避免视频流处理与常规设备点位采集相互耦合。

#### simulators：工业设备模拟器

用于模拟工业现场设备及通信环境，为网关开发、协议测试和系统联调提供测试数据。

主要功能：

- PLC 设备模拟。
- CNC 设备模拟。
- 工业设备运行状态模拟。
- 温度、压力、转速等数据模拟。
- 设备异常及故障模拟。
- 工业通信协议服务端模拟。

通过模拟器，可以在没有真实工业设备的情况下完成采集程序开发和测试。

### 4.2 工业物联网平台（platform）

负责工业网关管理、工业数据处理及上层业务服务，是整个系统的平台核心。

#### gateway-manager：网关配置管理平台

负责工业网关、工业设备及采集配置的统一管理，为边缘网关提供配置管理和运行监控能力。

主要功能：

- 网关注册与管理。
- 网关在线状态监控。
- 工业设备管理。
- 通信驱动配置。
- 设备点位管理。
- 采集周期及采集参数配置。
- 网关配置下发。
- 配置版本管理。
- 配置执行结果反馈。
- 网关运行日志管理。

该项目由前后端两个部分组成：

- backend：提供网关管理、设备管理、采集配置、配置下发等后端业务服务。
- frontend：提供网关管理、设备配置、点位管理及运行状态监控等管理界面。

#### data-center：工业数据中台

负责接收边缘网关上报的工业数据，对数据进行解析、标准化、存储和处理，为上层应用提供统一的数据服务。

主要功能：

- 工业数据接入。
- 数据解析与标准化。
- 设备及点位数据管理。
- 实时数据处理。
- 时序数据存储。
- 历史数据查询。
- 数据统计与分析。
- 数据服务接口。
- 基础告警规则及事件处理。

该项目由两个主要部分组成：

- backend：负责数据查询、数据管理、统计分析及对外 API 服务。
- ingestion：负责 MQTT 消息接收、数据解析、数据标准化及数据写入。

#### applications：工业应用

基于工业数据中台提供的数据服务，开发面向不同工业业务场景的应用。

各应用围绕具体业务需求独立设计，避免将业务逻辑与底层数据采集、存储功能混合。

**device-monitor：设备监控**

负责工业设备运行状态及实时数据监控。

主要功能：

- 设备运行状态展示。
- 设备在线状态监控。
- 实时设备数据展示。
- 设备历史数据查询。
- 设备运行情况统计。

**alarm-center：报警中心**

负责工业设备异常检测、报警管理及报警处理。

主要功能：

- 报警规则管理。
- 设备异常报警。
- 报警记录管理。
- 报警级别管理。
- 报警确认与处理。
- 报警历史查询。

**production-monitor：生产监控**

负责工业生产过程及设备生产状态监控。

主要功能：

- 生产设备运行状态。
- 生产任务监控。
- 设备运行时间统计。
- 生产数量统计。
- 生产过程数据展示。

**energy-management：能耗管理**

负责工业设备及生产过程中的能源数据统计与分析。

主要功能：

- 设备能耗统计。
- 能耗实时监控。
- 历史能耗查询。
- 能耗趋势分析。
- 能耗报表。

### 4.3 组态可视化层（visualization）

#### scada：工业组态系统

提供工业监控画面的可视化编辑及运行能力，使用户可以通过拖拽组件、绑定设备点位的方式，自定义工业监控界面。

主要分为三个部分：

**editor：组态编辑器**

负责工业监控画面的设计与编辑。

主要功能：

- 画布管理。
- 图形组件拖拽。
- 组件属性配置。
- 画面布局调整。
- 设备点位绑定。
- 组态画面保存。

**runtime：组态运行时**

负责加载和运行已经创建的组态画面，实现工业数据的实时可视化展示。

主要功能：

- 组态画面加载。
- 组件渲染。
- 实时数据绑定。
- 设备状态展示。
- 趋势曲线展示。
- 运行时数据刷新。

**components：组态组件**

提供可复用的工业可视化组件，供组态编辑器和运行时使用。

主要组件：

- 数值显示组件。
- 仪表盘组件。
- 趋势曲线组件。
- 状态指示灯。
- 电机、水泵、阀门等设备图形。
- 工业设备状态组件。

### 4.4 公共数据协议（contracts）

负责统一管理不同项目之间的数据结构和通信协议，保证工业网关、管理平台、数据中台及上层应用之间的数据格式一致。

#### telemetry：设备遥测数据协议

定义工业设备数据上报的统一格式。

包括：

- 网关标识。
- 设备标识。
- 点位标识。
- 数据值。
- 数据类型。
- 数据质量。
- 采集时间戳。

#### gateway-config：网关配置协议

定义平台与工业网关之间的配置交互格式。

包括：

- 网关标识。
- 配置版本。
- 设备连接参数。
- 通信协议类型。
- 点位采集配置。
- 采集周期。
- 配置下发结果。

### 4.5 部署配置（deploy）

负责整个系统的部署环境及基础设施配置。

主要包括：

- Docker Compose 编排。
- MQTT 消息服务部署。
- MySQL 数据库部署。
- Redis 缓存服务部署。
- InfluxDB 时序数据库部署。
- Nginx 反向代理配置。
- 环境变量及部署配置模板。

目标是逐步实现整套系统的容器化部署，降低项目部署和运行环境配置成本。

## 六、开发计划

项目采用模块化、分阶段的方式开发，优先打通核心工业数据链路，再逐步完善上层业务。

| 阶段     | 开发内容           | 主要目标                            |
| -------- | ------------------ | ----------------------------------- |
| 第一阶段 | industrial-gateway | 完成 C++ 网关基础框架及典型协议采集 |
| 第二阶段 | contracts          | 统一设备遥测数据及网关配置格式      |
| 第三阶段 | gateway-manager    | 实现网关、设备、点位管理及配置下发  |
| 第四阶段 | data-center        | 实现 MQTT 数据接入、存储和查询      |
| 第五阶段 | applications       | 实现设备监控、报警及能耗等工业应用  |
| 第六阶段 | scada              | 实现组态编辑器及实时运行            |
| 第七阶段 | video-gateway      | 实现工业视频设备接入与视频流处理    |
| 第八阶段 | deploy             | 完善系统部署、联调及自动化测试      |

项目优先保证核心模块能够独立运行，再逐步完成跨模块集成。

## 七、项目设计原则

1. **模块化设计**：不同业务模块保持相对独立，减少模块之间的耦合。
2. **统一数据标准**：通过公共数据协议统一网关、平台及应用之间的数据结构。
3. **边缘与平台分离**：边缘网关负责现场设备接入和数据采集，平台负责集中管理和数据处理。
4. **配置驱动**：尽量通过平台配置控制网关采集行为，减少现场程序的重复修改和部署。
5. **可扩展性**：通过统一驱动接口和标准数据模型，支持后续扩展更多工业设备、通信协议及业务应用。
6. **可部署性**：逐步完善容器化部署及自动化测试能力。
