# 配置指南

本文说明如何配置当前 `industrial_gateway` 可执行程序，包括本地启动配置、平台动态采集配置和 Modbus TCP 字段。MQTT Topic 与 ACK 契约见 [MQTT 通信协议](MQTT通信协议.md)，恢复和应用机制见 [系统架构](系统架构.md)。

## 1. 两类配置的职责

| 配置 | 格式与来源 | 内容 | 生效方式 |
|---|---|---|---|
| 网关基础配置 | 本地 `gateway.yaml` | 网关 ID、日志、MQTT、SQLite | 启动读取；修改后需重启进程 |
| 动态采集配置 | MQTT JSON 完整快照；SQLite 保存最近目标 | 协议连接、设备、点位及采集周期 | 配置线程校验、保存并应用；重启先恢复本地记录 |

两者的 `schema_version` 都只表示各自文件或消息的结构版本，当前均为 `1`，不表示配置更新次数。动态消息不能修改网关 ID、日志、Broker 或数据库路径。

主 YAML 的 `connections` 是保留的静态配置模型入口。**当前 Runtime 只接受空列表或省略该字段**，不从静态协议文件创建采集连接。协议工厂虽然支持静态 YAML，但不能因此把非空静态连接列表直接用于当前主程序。

## 2. 本地 YAML 示例

以下是使用默认日志、存储和 MQTT 参数时的最小结构：

```yaml
schema_version: 1
gateway:
  id: "industrial-gateway-001"
```

注意：省略 `mqtt` 仍会默认启用 MQTT，并使用 `127.0.0.1:1883`。要禁用必须显式设置 `mqtt.enabled: false`。

完整示例：

```yaml
schema_version: 1

gateway:
  id: "industrial-gateway-001"

logging:
  level: info
  console_enabled: true
  file_enabled: true
  file_path: "logs/gateway.log"
  rotation:
    strategy: size
    max_size_bytes: 10485760
    max_files: 5

mqtt:
  enabled: true
  host: "127.0.0.1"
  port: 1883
  client_id: "industrial-gateway-001"
  keep_alive: 60

storage:
  database_path: "data/gateway.db"
  busy_timeout_ms: 5000

# 当前主程序通过 MQTT 下发和 SQLite 恢复创建采集连接。
connections: []
```

示例中的 Broker 地址使用本机地址，仓库 [config/gateway.yaml](../config/gateway.yaml) 则填写了开发环境地址。两者都需要按实际部署环境选择。下面“默认值”指代码默认值，不代表仓库示例中填写的值。

## 3. 本地字段参考

### 3.1 顶层与网关身份

| 字段 | 类型 | 必填 / 默认值 | 约束与说明 |
|---|---|---|---|
| `schema_version` | 整数 | 必填 | 当前只接受 `1` |
| `gateway` | 映射 | 必填 | 包含网关身份 |
| `gateway.id` | 字符串 | 必填 | 非空、非全空白；运行时还要求不含 `/`、`+`、`#` 和 NUL，作为单个 MQTT Topic 层级 |
| `logging` | 映射 | 可省略 | 使用日志默认值 |
| `mqtt` | 映射 | 可省略 | 使用 MQTT 默认值，默认启用 |
| `storage` | 映射 | 可省略 | 使用存储默认值 |
| `connections` | 数组 | `[]` | 当前入口必须为空；`null` 无效 |

`gateway.id` 决定业务 Topic；`mqtt.client_id` 是 Broker 连接标识。两者可以不同，不会自动同步。部署多个网关时，应分别设置合适的唯一身份，避免连接 ID 冲突。

修改 `gateway.id` 不会自动迁移或清空 SQLite：现有遥测 JSON 没有网关 ID，积压消息会按新运行配置的 Topic 发送，本地快照也会继续恢复。因此重新分配网关身份时，应同时明确数据库归属。

### 3.2 日志

| 字段 | 类型 | 默认值 | 约束与说明 |
|---|---|---|---|
| `logging.level` | 字符串 | `info` | `trace`、`debug`、`info`、`warn`、`error`、`critical` |
| `logging.console_enabled` | 布尔 | `true` | 控制台输出开关 |
| `logging.file_enabled` | 布尔 | `true` | 文件输出开关；两种输出不能同时关闭 |
| `logging.file_path` | 字符串 | `logs/gateway.log` | 启用文件输出时不能为空或全空白 |
| `logging.rotation.strategy` | 字符串 | `size` | 当前只支持按文件大小滚动 |
| `logging.rotation.max_size_bytes` | 整数 | `10485760` | 启用文件输出时为 1..2147483648 字节，即最大 2 GiB |
| `logging.rotation.max_files` | 整数 | `5` | 启用文件输出时为 1..49；只计历史文件，不含当前文件 |

禁用文件输出会跳过文件参数的部分语义校验，但显式提供的字段仍需能被解析为对应类型，枚举值仍需合法。建议保持合法默认值，不依赖禁用开关容忍错误配置。

### 3.3 MQTT

| 字段 | 类型 | 默认值 | 约束与说明 |
|---|---|---|---|
| `mqtt.enabled` | 布尔 | `true` | 是否启动配置订阅、MQTT 网络线程和发布线程 |
| `mqtt.host` | 字符串 | `127.0.0.1` | 启用时非空、非全空白；填写 Broker 主机名或 IP，不填写带协议的 URL |
| `mqtt.port` | 整数 | `1883` | 启用时为 1..65535 |
| `mqtt.client_id` | 字符串 | `industrial-gateway-001` | 启用时非空、非全空白，长度不超过 65535 字节；Broker 可能有额外限制 |
| `mqtt.keep_alive` | 整数 | `60` | 启用时实际可启动范围为 `0` 或 `5..3600` 秒；`0` 禁用协议 Keep Alive |

当前通用配置校验器对 `keep_alive` 接受 0..65535，但 MQTT 客户端启动阶段进一步限制为 `0` 或 `5..3600`。例如 `1` 或 `4000` 可能通过 YAML 校验，却在启动 MQTT 时失败；本文按完整启动链路给出范围。

`keep_alive` 是 MQTT 协议参数，不是业务心跳上报周期。当前没有 `username`、`password`、`tls`、`qos`、`retain` 等 YAML 字段，添加这些键会被拒绝；遥测与配置 ACK 发布使用固定 QoS 1、retain=false。

禁用 MQTT 后不接收动态配置，不发送遥测与 ACK；配置恢复、采集和入库仍继续。此时连接参数不做启用状态下的语义范围校验，但显式字段的结构与类型仍需合法。

### 3.4 SQLite 与路径

| 字段 | 类型 | 默认值 | 约束与说明 |
|---|---|---|---|
| `storage.database_path` | 字符串 | `data/gateway.db` | 非空、非全空白，不含 NUL；需要可写的文件位置 |
| `storage.busy_timeout_ms` | 整数 | `5000` | 0..60000 毫秒；`0` 不等待数据库锁 |

主配置参数省略时，从进程工作目录读取 `config/gateway.yaml`。日志和数据库的相对路径也按**进程工作目录**解析，传入绝对 YAML 路径不会改变这一基准。

例如在项目目录执行 `./build/industrial_gateway /etc/gateway/gateway.yaml`，文件内的 `data/gateway.db` 仍指向项目目录下的 `data/gateway.db`，不是 `/etc/gateway/data/gateway.db`。服务部署可固定工作目录，或在 YAML 中填写绝对路径。

程序尝试创建日志和数据库父目录。SQLite 使用 WAL 模式，数据库目录还需要允许创建和写入相关辅助文件。`busy_timeout_ms` 只控制锁等待，不是存储重试总时限或进程退出时限。

### 3.5 本地解析规则

- YAML 根节点和 `gateway`、`logging`、`mqtt`、`storage` 等配置段必须是映射；显式 `null` 不等于省略字段。
- 未知字段会被拒绝，枚举字符串区分大小写。
- 当前本地解析器使用 yaml-cpp 的标量转换规则；示例统一使用无引号整数、`true/false` 和带引号文本，避免依赖隐式转换。
- 不要使用重复键；顶层、`gateway` 和静态连接项会显式拒绝重复键，日志/MQTT/存储子解析器未提供相同的重复键检查保证。

## 4. 动态采集配置

平台每次发送的 JSON 都是**全部连接的目标快照**。修改一个连接时，也必须包含仍需保留的其他连接；快照中缺失的已有连接会被移除。

| 字段 | 类型 | 约束 |
|---|---|---|
| `schema_version` | JSON 整数 | 必填，固定为 `1` |
| `request_id` | 字符串 | 必填，非空、非全空白、不含 NUL；用于关联业务 ACK |
| `connections` | 数组 | 必填；`[]` 表示清空全部采集连接 |
| `connections[].connection_id` | 字符串 | 必填，非空、非全空白、不含 NUL；同快照内唯一 |
| `connections[].protocol` | 字符串 | 必填，当前为 `modbus_tcp`、`modbus_rtu` 或 `opcua` |
| `connections[].config` | 对象 | 必填，由对应协议解析器校验 |

JSON 严格拒绝未知字段、重复键和不符合字段类型的值，不支持注释。整数不能写成字符串、小数或布尔值。旧字段 `config_version` 不受支持。

公共层校验连接 ID 唯一性，协议工厂进一步校验端点和点位；相同协议的重复端点也会被拒绝。`device_id` 是平台逻辑身份，内置协议使用 int64，当前不要求为正数，唯一性在同一连接内检查。平台应自行确保跨连接的设备身份安排符合业务要求。

`request_id` 不是版本号，也不会阻止同 ID 请求重复应用。配置按入队顺序处理；具体 ACK、重发和 retained 使用方式见 [MQTT 通信协议](MQTT通信协议.md)。

## 5. Modbus TCP 配置

### 5.1 完整示例

```json
{
  "schema_version": 1,
  "request_id": "config-request-001",
  "connections": [
    {
      "connection_id": "modbus_tcp_001",
      "protocol": "modbus_tcp",
      "config": {
        "connection": {
          "host": "192.168.0.10",
          "port": 502,
          "connect_timeout_ms": 1000,
          "response_timeout_ms": 1000
        },
        "devices": [
          {
            "device_id": 10001,
            "unit_id": 1,
            "points": [
              {
                "property": "temperature",
                "address": 0,
                "register_type": "holding",
                "data_type": "float32",
                "byte_order": "high_byte_first",
                "word_order": "high_word_first",
                "interval_ms": 5000,
                "scale": 1.0,
                "offset": 0.0
              },
              {
                "property": "speed",
                "address": 2,
                "data_type": "uint16",
                "interval_ms": 5000
              }
            ]
          }
        ]
      }
    }
  ]
}
```

这里一个任务每 5 秒读取设备 10001 的两个点位，连续覆盖保持寄存器 0..2。实际 IP、Unit ID、寄存器地址和解码顺序必须按设备寄存器表修改。

### 5.2 连接和设备字段

下表中的路径相对于 `connections[].config`。

| 字段 | 必填 / 默认值 | 约束与含义 |
|---|---|---|
| `connection` | 必填对象 | TCP 连接参数 |
| `connection.host` | 必填字符串 | 当前驱动只支持数字 IPv4，不支持域名和 IPv6 |
| `connection.port` | `502` | 整数，1..65535 |
| `connection.connect_timeout_ms` | `1000` | 正整数毫秒，单次连接超时 |
| `connection.response_timeout_ms` | `1000` | 正整数毫秒，单次读取等待响应的超时 |
| `devices` | 必填数组 | 至少一个设备 |
| `devices[].device_id` | 必填整数 | int64 范围，同连接内唯一；与 Unit ID 不同 |
| `devices[].unit_id` | `1` | 整数，0..247 或 255；按设备要求使用，TCP 的 0 不表示支持串行广播读取 |
| `devices[].points` | 必填数组 | 至少一个点位 |

两个超时参数还受 libmodbus 表示范围限制：换算后的整秒部分不能超过 uint32 最大值。它们分别约束单次连接或读取，不是多设备任务或全局关闭的总时限。

### 5.3 点位字段

| 字段 | 必填 / 默认值 | 约束与含义 |
|---|---|---|
| `property` | 必填字符串 | 非空、非全空白、不含 NUL，同设备内唯一 |
| `address` | 必填整数 | 零基地址 0..65535，完整数值占用范围也不能越界 |
| `register_type` | `holding` | `holding` 或 `input`，不支持线圈、离散输入或写操作 |
| `data_type` | `uint16` | `int16`、`uint16`、`int32`、`uint32`、`int64`、`uint64`、`float32`、`float64` |
| `byte_order` | `high_byte_first` | 或 `low_byte_first`；单个寄存器内部的数值字节顺序 |
| `word_order` | `high_word_first` | 或 `low_word_first`；多寄存器数值的字顺序，单寄存器类型忽略 |
| `interval_ms` | `1000` | 正整数毫秒；还需能被调度器单调时钟表示 |
| `scale` | `1.0` | 有限数值 |
| `offset` | `0.0` | 有限数值；工程值 = 解码值 × scale + offset |

16 位数占 1 个寄存器，32 位数占 2 个，64 位数占 4 个。不要添加 `quantity`，数量由类型推导；也不要直接填写手册中的 `4xxxx` 引用编号。

同一设备、同一周期的点位必须使用相同寄存器类型，全部点位的连续覆盖范围不能超过 125 个寄存器。范围中的间隙地址也会读取，必须确认设备允许访问；当前不会自动拆分成多次读取。

默认缩放保留整数为 int64/uint64，浮点数输出为 double；非默认缩放统一输出 double，大整数可能损失精度。读取、解码或工程值转换失败时，该设备在本次任务中整体失败，不返回部分成功点位。

## 6. RTU、OPC UA 与多协议组合

| 协议 | 主要配置区别 | 详细说明 |
|---|---|---|
| `modbus_rtu` | 串口路径、波特率、校验、串口模式及恢复等待；从站地址为 1..247 | [Modbus RTU 协议适配](modbus_rtu.md) |
| `opcua` | Endpoint URL、NodeId、操作超时；只接受匿名与 None 安全策略 | [OPC UA 协议适配](opcua.md) |

将各协议示例中的连接对象合并到**同一个** `connections` 数组即可混用。依次发送三个只含单个协议的快照，会依次替换整个目标集合，不能达到同时启用三个协议的效果。

不同采集周期会生成不同任务和遥测包；即使属于同一设备，也不保证所有属性出现在每个包里。平台应按每条记录的 `property` 更新数据，不把当前包缺失的属性视为删除。

## 7. 常见修改与恢复行为

| 操作 | 当前行为 |
|---|---|
| 修改 Broker、日志或存储路径 | 修改本地 YAML 后重启 |
| 修改点位、频率、设备或协议参数 | 下发完整快照；变化连接停止后重建，期间可能短暂中断 |
| 重发相同快照 | 重新校验并保存；未变化且仍运行的连接可复用 |
| 清空采集连接 | 下发 `connections: []`；不删除已入库遥测 |
| 首次启动无本地快照 | 等待平台配置，不创建采集连接 |
| MQTT 离线但有本地快照 | 恢复并继续采集入库，连接恢复后补传 |
| 本地配置无法通过校验 | 保留记录、记录错误，等待平台修正 |
| 有效配置应用中途失败 | 可能部分生效，保留目标 JSON 并进入故障关闭流程，无自动回滚 |

不要通过直接修改 SQLite 来代替正常配置下发。配置持久化顺序、ACK 不送达和关闭阻塞等边界，分别见 [系统架构](系统架构.md) 与 [MQTT 通信协议](MQTT通信协议.md)。

## 8. 参数的当前开放范围

队列容量、遥测批量大小、发布确认等待时间、重试间隔和健康检查周期目前是代码常量，没有对应 YAML 配置项。文档中的这些运行参数用于理解现有行为，不能直接作为新字段添加到配置文件。
